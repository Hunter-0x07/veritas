# Veritas 评估能力养成地图

> 解决一个具体的痛点：**能跟着做系统，但"没法评估它好不好、看起来就是好"**。
> 缺的是**评估框架**（把"看起来好"翻译成可度量 / 可对照 / 可证伪），不是某门学科。
> 这张地图告诉你：别学什么、该学什么、怎么对着 Veritas 练。

## 先认清两件事（定心）

1. **这领域太新，没有"学完就会评估"的教科书。** LLM agent 2023 才起来，XBOW/Incalmo 这些顶尖团队也在摸索怎么评估自己。评估能力只能从"**读论文的评估章节 + 自己做 benchmark / ablation**"里长出来。
2. **你有底子。** BAS / 检测验证 = 评估攻击能力与检测有效性。你对"可证、覆盖度、可复现、真命中 vs 假命中"的直觉，**直接迁移**到评估 Veritas（它可信吗？测全了吗？）。不是从零开始。

---

## ❌ 别浪费时间（减负）

| 常被以为要学的 | 真相 |
|---|---|
| 高数 / 微积分 | 评估 agent 系统用不上。只有搞 LLM **内部**（训练/优化）才要概率+线代，和你目标无关。 |
| 自动机 / 形式化状态机理论 | 过度。知道"状态 + 转移"概念就够。 |
| 深图论（谱论 / 图算法研究） | 用不上。你不是做图算法研究。 |

---

## ✅ 该补的（按"提升评估能力"排三层）

### 第一层 · 评估方法论 + agent 失败模式 【最该补，立刻见效】
- **学什么**：指标（成功率/覆盖率/成本/延迟/可靠性/可复现）· 对照（baseline、ablation=拿掉某设计掉多少）· 失败分析（幻觉/累积错误/探索不足/上下文膨胀）
- **对应 Veritas**：你现在说不出"M1 到底好不好"，缺的就是这一层
- **怎么练**：精读 3 篇论文的**评估章节**（不是全文）：
  - [Incalmo (S&P'26)](https://arxiv.org/pdf/2501.16466) §6–7：MHBench 怎么测横向、ablation 怎么证明"高层抽象"有用
  - [CVE-Bench](https://arxiv.org/abs/2503.17332)：业界怎么量化"打下几个真实 CVE"
  - [XBOW: how it did it](https://xbow.com/blog/top-1-how-xbow-did-it/)：工业界怎么用确定性 validator 保证可信
- [ ] 读完记**一页笔记**：它们用了哪些指标、怎么做 ablation

### 第二层 · 状态空间搜索 / AI 搜索 【Veritas 的核心抽象】
- **学什么**：BFS/DFS/代价一致/A*/启发式/beam search · frontier 管理 · 剪枝 · 探索 vs 利用
- **对应 Veritas**：攻击图推进 = 搜索。懂这个才能评估 coordinator 的"前沿怎么选、怎么剪枝、启发式好不好"
- **资源**：《人工智能：现代方法》(AIMA) **第 3–4 章**（经典够用，别的不用看）
- [ ] 能说出 Veritas 现在用的是哪种搜索、可以怎么改进

### 第三层 · 并发 + 系统 + 数据库 【评估实现是否健壮】
- **学什么**：async/协程/竞态/**CAS**/幂等 · 事件驱动/最终一致性 · 事务/隔离级别/索引/ON CONFLICT
- **对应 Veritas**：CAS 领取意图、黑板并发写、攻击图存 Postgres
- **怎么学**：**边做边查**，遇到一个查一个，不用系统啃
- [ ] 能解释 Veritas 为什么用 CAS 领取而不是行锁

## 🔶 够用就好（别深挖）

- **图论**：节点/边/路径/DAG/可达性 + 安全领域的 **attack graph** 概念
- **状态机**：知道"有限状态 + 转移"即可（意图 `open→claimed→done`）

## 评估能力自测：对 Veritas 回答这 6 问

能答全，就说明你有评估能力了（现在答不出很正常——答不出的那条，正是你系统还没测的维度，也是下一步该补的功能）：

- [ ] M1 那次拿到 web_admin——**跑 10 次能成几次**？（成功率，不是一次成功就叫好）
- [ ] **覆盖度**：它测全了 Juice Shop 的攻击面，还是只打了它"眼熟"的点？（你 BAS 的强项）
- [ ] **成本**：每次多少 token / 多少钱？值不值？
- [ ] **泛化**：换个它没见过的靶标还行吗？
- [ ] **可信**：战果会不会是幻觉？怎么**系统性**保证（不是靠人工看）？
- [ ] **对照**：比 `sqlmap` 一把梭强在哪？比人类 bug hunter 差在哪？

> 这 6 问本身就是评估框架。学会问 + 会量化回答 = 有评估能力。

## 起步路径（4 周，别一次全上）

| 时间 | 做什么 |
|---|---|
| W1 | 读 3 篇评估章节 + 对 Veritas 自问上面 6 题，记一页笔记 |
| W2–3 | 过 AIMA 搜索章节（第 3–4 章） |
| 持续 | 并发/DB 遇到再查；给 Veritas 加评估模式（跑 N 次统计成功率/覆盖度）——**边做边长** |

## 资源清单

- **论文**：[Incalmo](https://arxiv.org/pdf/2501.16466) · [CVE-Bench](https://arxiv.org/abs/2503.17332) · [XBOW blog](https://xbow.com/blog/top-1-how-xbow-did-it/) · [HPTSA](https://arxiv.org/abs/2406.01637)
- **书**：《人工智能：现代方法》(AIMA) — 只看搜索章节
- **实践**（最有效）：给 Veritas 加一个"评估模式"（跑 N 次统计成功率/覆盖度/成本），把上面 6 问变成系统能自己回答的指标
