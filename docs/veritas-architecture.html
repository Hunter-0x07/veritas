01第一性原理

渗透 = 在「攻击图」上搜索一条从初始立足点通往目标权限/数据的路径。每成功利用一个漏洞 = 一次访问权限的跃迁。进展用访问级别度量，不用"发现了几个漏洞"——这是与"漏洞扫描器/验证器"的根本分野。

05关键设计抉择（取 / 舍 / 融合）

抉择点决定理由
决策/执行分层混合：确定性动作走 Incalmo 式声明执行器；Web 利用走 Strix 式自由沙箱Web 利用千变万化，固定动作集表达不了；横向/扫描/破解/登录模式固定、是状态骨架。按动作确定性程度分治，不强塞。
舰队策略分解派生为主，局部冗余重试为辅渗透是广度/多目标；全量冗余成本高。ARTEX 的"fresh session+图为权威+trace 互查"已解决累积错误。
意图领取条件 UPDATE CAS，弃 SKIP LOCKED横向多 worker 抢同一前沿，CAS 无死锁无长事务，配崩溃重领更合适。
执行器工具沙箱 shell + 薄知识包，不逐个 wrap 工具Strix 验证过：给 Kali 沙箱跑 CLI 比为每个扫描器写 wrapper 灵活。
验证能力降级为 Executor 的"动作成功判定"v1 没白做——变成"利用是否真成功"的判定，服务推进而非列漏洞。
上下文治理冷图 digest 压缩 + 结构化安全 checkpoint多主机横向让图爆炸，冷图是长程省成本关键，且算法层可直接移植。
砍掉/后置SARIF/auto-fix、资产同步、Web UI、MCP、复测AppSec 修复/企业资产/运营设施，非挖洞+渗透内核，后期按需。

06诚实的闭环判断

能力能闭环实际效果
Web 漏洞挖掘（挖 HackerOne 主体）✓ 能达到活跃 bug hunter 的广度与速度，中低危有稳定产出；顶尖高危/业务逻辑仍需人。
Web 利用链（dump→凭据→提权）✓ 能单机 web 走完"发现→利用→提权"串行链（v1 缺的核心）。
Web→内网横向半靶场/已知 N-day 能闭环；真实企业内网（EDR/分段）是全行业能力边界 → 人机协同。
后渗透/提权半已知提权可自动，复杂提权需人。

定位：自动化广度漏洞发现 + PoC 验证 + 已知路径横向。挖 HackerOne 这条线能产生真实价值且可闭环；全自动打穿真实域控是能力边界，设计上为 HITL 留接口，不假装全自动。

07路线图（按"完成什么样"定义，非时间）

每个里程碑 = 一个可验证的能力状态。做完一个才进下一个。

M0 · 骨架能推进 （下一步）
攻击图+Coordinator+Solver+Executor 接口齐备；mock 演示完整 kill chain（external→web_user→凭据→内网 host→shell），goal 达成即停、输出 kill chain。不接真实目标、不烧 token。证明"推进"跑通。
M1 · 单机 Web 能真打
external recon + 自由沙箱 Web Solver（Kali shell+代理+浏览器+知识包）对真实 web 靶标自主发现并利用漏洞，产出真实 foothold/credential 写回攻击图。靶标 Juice Shop。
M2 · Web 利用链闭环
走完多步串行链 SQLi→dump→拿 hash→crack→用凭据登录→提权到 web_admin，由共享 todolist 按依赖调度。证据纪律在线（反蜜罐）。
M3 · 多主机横向闭环
从 web 立足点内网发现 + 声明式横向动作（凭据复用/ssh/smb/winrm）+ pivot 代理，攻击图长出内网主机并拿到 shell@内网host。"从 web 到内网横向"的验收点。
M4 · 规模化 + 结论可信
并行 solver 舰队 + trace 协作 + Observer 监督 + 全链路 MITM 留痕 + kill chain 报告（带每一跳 PoC）。能并行多目标、结论不误报、报告可交付。
M5 · 长程 + 工程化
冷图压缩 + 跨 run 策略记忆（向量库）+ 分级自主/审批门 + 多 provider + kill chain 可视化回放。
